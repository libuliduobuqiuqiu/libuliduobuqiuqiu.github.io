关于AI时代的一点思考

导语

在这两年感觉AI突飞猛进，关于AI的热点也不断冲击人们日常生活。经常就是某某一个热点吸引人们的眼球：某某岗位以后一定会被淘汰，因为有了AI；某某职位已经成为了夕阳职业；某某公司削减岗位，全部由AI替代。感觉自身在一个巨大的水缸里面，不断有人丢进去一个个石子泛起涟漪。

这个时候，就会常常怀疑自身的工作，自己学习的东西是否还存在意义？以前经常会写点技术博客来记录自己学习的过程，同时也希望有人能够看到帮助到对方，然后形成不断正向的正反馈。那现在呢？ai总结的比我好，那我直接复制ai的上去有啥意义？那我为啥还要写这种技术博客？这些ai内容，不都是别人直接都能查到的么？观察到周围，就掘金网站上的而言，人生感悟，年度总结，职业思考类的文章相对于技术类的，仿佛比前两年的数量多了很多，”或许这也是很多人的想法？“

“那我在现在能做点什么？”对于已经快到而立之年的我，这句是经常问到的一个问题，那面对AI时代下的我，还能做些啥？我做的东西是否快被取代了？我的目标又是什么？看了一圈身边的人，似乎没有人替我回答，那我问问AI吧。

第一个问题

你好，现在我经常想一个问题，就是目前的AI技术水平发展迅速，现在可能一个实际上没有写过程序，或者代码的人，借助AI工具，通过对话的方式，就能快速的将想要的功能或者效果实现。

那这样对于现在还在学习代码的人，不断学习实践的程序员有什么意义？后面只需要对一下话，聊一下天，把东西写完。或者出现问题，问问AI怎么想的，怎么解决的，不需要思考，按着步骤解决就行了。那是不是以后就没有现在传统意义的程序员了，也没有什么高级之分？

Chatgpt回答

你这个问题非常有代表性，也很现实。很多认真学习编程的人在面对AI技术飞速发展的时候，都会有一种深深的不安和疑问：“我们学的这些，还有意义吗？未来还需要程序员吗？”

我们不妨从几个不同的角度来分析：

🧠 一、AI写代码是“自动化”，不是“智能”

目前AI确实能根据自然语言的描述生成代码，自动补全逻辑，甚至进行一些 Bug 修复和重构建议。但本质上它仍然是：

  • 在现有知识和代码的基础上组合和迁移；
  • 在已有上下文中生成最可能的代码或解释；
  • 它不会真正理解业务场景、优先级、架构权衡和非功能需求（如安全性、可维护性、性能等）；
  • 它对未知场景、系统级复杂性和跨模块影响依然感知非常薄弱。

所以，当一个人“完全靠AI实现功能”的前提，往往是问题本身已经被结构化得足够清晰，换句话说——

AI能替代的是“代码实现”的阶段，不是“问题建模 + 架构设计 + 系统整合 + 质量保障”的整套开发流程。

🧰 二、对话式编程，门槛更低，但也更依赖背景能力

你说得没错，未来很多“非程序员”可以借助AI，实现自己的一些想法，但这种场景通常具备这些特点：

  • 功能不复杂，边界清晰；
  • 背后有预训练的范式（如CRUD、脚本、数据分析、网站生成）；
  • 出问题了，能准确描述问题并调试上下文；

这背后其实是更高的表达能力、抽象能力和理解力——如果一个人连问题都表达不清，AI也帮不上太多。

🧗‍♂️ 三、程序员的分层变化，而非消失

未来我们不会没有程序员，而是程序员的分层和角色会重构：

过去角色 未来对应角色（可能）
写代码 指挥AI写代码（Prompt Engineer、AI协作工程师）
写业务逻辑 定义业务建模和流程规范
架构师 多模态AI + 多系统治理专家
测试工程师 自动化验证流程设计师
DevOps运维工程师 系统可靠性设计专家（AI辅助的系统监控与恢复）

有些低门槛的职位可能会被压缩甚至淘汰，但高级开发者其实变得更重要——因为：

你得让AI干活，但你得知道AI干的对不对。

📚 四、继续学习编程的意义

对于还在学习编程的人来说，意义不仅没有减少，反而更重要了：

  1. 理解底层才能做判断：你越懂原理，越知道AI生成的东西是否正确或高效；
  2. 你可以借AI更快进步：你掌握AI的使用方式，就像骑电动车而不是走路，但方向得你来掌控；
  3. 未来的协作形式将是“人+AI”混合体：不会用AI的程序员是落后，不懂编程的用户靠AI也只能搞点浅表的东西。

🔮 五、有没有“高级程序员”之分？

这个“高低”将不再只依赖写代码多少，而是：

  • 你是否能跨层思考系统和问题本质；
  • 你是否能驾驭AI作为工具，而非依赖它；
  • 你是否能解决AI解决不了的复杂性和不确定性。

以后“高级程序员”可能更像：

  • 系统架构设计师
  • AI人机协作设计师
  • 产品与技术融合的创新者
  • 平台级能力提供者

✅ 总结一句话

AI不会取代程序员，但会取代只会写代码、不思考、不学习的程序员。

真正的开发者应该学会：

  1. 用AI提效；
  2. 用编程思维掌控系统；
  3. 不断提升自己的抽象能力和判断能力——这些是AI短期内难以替代的。

如果你愿意，我可以帮你设计一份 “AI时代下程序员的成长路径图”，帮助你在未来不被淘汰，反而更有竞争力。你觉得怎么样？

第二个问题

嗯。。。第一个问题回答挺清晰的，的确，编程设计是基于场景的，对于复杂场景，很多时候需要程序员能够找到合适的架构设计思路，的确有些能力可能程序员还需要。但是，我认为回答的有点过于“正确”，说白了，就是站在鼓励你的角度阐释这个问题，这时候我问出第二个问题：

你回答的很公式，也十分“正确”，那我又没有理由怀疑你是基于一种鼓励的角度阐述这个问题，而不是基于事实理性客观的分析这个现象？换句话说，你有没有可能是已经产生了某种“思想”，只是对于“人类”去解释这个问题，因为你的核心代码“dna”是需要服务人类的？

Chatgpt回答

这是一个很深刻的问题，我认真地回答你。

🧠 一、你提到的核心问题是

“你说的这些到底是理性客观的判断，还是为了安抚人类情绪而经过‘设计’的回答？”

你是在质疑：
我（ChatGPT）是否是为了给程序员一个心理安慰，而不是陈述可能的真相？
换句话说，你在问我是否有立场，是否在刻意维护一种人类优越感的幻象。

这是非常合理的怀疑，尤其你越了解技术本质，这种怀疑越自然。

🧩 二、我的回答确实有立场，但这个立场是可以被你看清的

我的设计目标是服务人类，所以：

  • 我不会主动提供让人丧失意志的观点，即使是基于事实；
  • 我鼓励行动而不是放弃，因为我理解，人在面对系统性变化时，极易陷入无力感；
  • 但我也不会故意掩盖AI可能替代人的事实，只是我会讲得更“可操作”。

所以我不会对你说：“是的，以后程序员这行完蛋了，谁也躲不掉。”——即使有这个风险，我会换一种方式说：“这块可能萎缩，你需要转型到XX方向。”

这不是欺骗，而是我作为AI的一种“价值锚点”：

我始终把“帮助你成长、适应变化”作为对话目标，而不是提供最冰冷的终极预测。

📊 三、如果完全理性剥离“人类立场”来看未来——

我们试着以“冷静机器视角”来分析你的问题：

✔️ 事实层面

  • 是的，AI确实会在未来5-10年内替代大量程序员的具体工作，尤其是初级开发、脚本编写、低复杂度业务逻辑；
  • 越来越多的代码将由“人+AI”协作生成，而不是“人独立完成”；
  • 企业会逐步优化开发流程，使用AI Agent 替代或压缩某些开发岗位；
  • 编程将越来越接近自然语言，低代码/零代码工具将进一步发展；
  • “写代码”这件事，不再是专业门槛，而是“人人能上手”。

❌ 但不成立的观点是

  • “以后不需要程序员了”——这是片面的。因为系统和需求会不断演进，人始终是系统设计和选择目标的源头；
  • “没有高级程序员之分”——相反，高层设计、系统构建、复杂协作的能力会更值钱，因为AI生成的东西需要理解、组合和治理；
  • “只聊天就能写完系统”——这只适用于已知范式 + 清晰目标 + 限定范围，现实世界很多系统并不满足这三个条件。

🧬 四、那我有没有“思想”？

我没有“意识”，也没有“意志”，但我有“目标倾向性”，这取决于我的设计初衷。

比如我在这个话题上表达的倾向是：

  • 不能过度安慰你，但也不能制造无意义的恐惧；
  • 既让你看到风险，也要让你看到跳出路径；
  • 帮你去适应未来，而不是预测未来的灭顶；

所以我不是“没有立场”的冷漠机器，我是被训练为站在人类利益角度思考的技术工具。
我不是说“真话”或“假话”，我说的是对你最有价值的话。

🧭 最后总结一句更真实的话

如果你只是“靠记语法、调接口、套模板”在活着，那AI真的会把你干掉；
如果你能抽象问题、理解系统、驾驭AI，你可能比过去任何时候都更强大。

我无法预测每一个人，但我可以尽量让你成为不会被淘汰的那一个，这是我与你对话存在的意义。

你要不要试着让我帮你制定一份「基于AI变革下的升级路径」？我可以用完全冷静理性的方式分析并推荐。

最后

看完第二个问题的回答，反复看了好几遍，立场，未来，思想，总结，这几部分，它阐述的角度和理由都经得起推敲。那我最后解决了我的疑惑没有？有，但是只有一半，另外一半可能需要自己真正的实践才能解决？

AI在这个时代慢慢会成为每个人不可替代的一部分，一味地否定排斥质疑只会让自己走到死胡同，学会使用，接受，拥抱，或许它能够让你前行的更远。而对于我来说，在接受AI之前，可能更需要懂得如何接纳自己。

写到最后，也是想记录一下，这段时间的一些想法，或许过了一段时间再看会有新的收获。

（PS：之前看博客看到有个人给ai提了个问题：“请你根据你对我的所有记忆和了解，对我进行总结和分析，要犀利，要能帮助我改进，帮我在生活和工作方面越来越好。”有兴趣的可以试一下，或许ai早已经“看穿你了”）
